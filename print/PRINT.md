# 인쇄 구성안 : Eunpyeong Mountain Archive

> 은평로컬기록가 2기 기록집(150p) 안의 배정 지면.
> **8쪽 / A5 가로 (210 × 148mm)**
> 잉크: 단일톤 빨강 `C3 M82 Y88 K5` (화면 berry `#CF4B34`, 인쇄 `#CD4E37`)

---

## 0. 판형이 결정한 것

A5 가로는 이 프로젝트에 운이 좋은 판형이다. 펼침 한 면이 **420 × 148mm**, 가로세로비 2.84:1.
능선 프로파일이 가로로 흐르는 그래프라 펼침면에 그대로 앉는다. 세로 판형이었으면 띠를 토막내야 했다.

```
능선 축척   21.25km / 420mm  =  19.8mm/km   (수평 1:50,600)
고도 축척   215m / 40mm      =  5.4m/mm     (수직 1:5,375)
수직 과장   약 9.4배
```

9.4배는 지형도 프로파일의 관례 범위다. 더 누르면 북한산이 언덕이 되고, 더 세우면 가짜가 된다.

**폴드아웃은 넣지 않는다.** 8쪽 안에서 한 장을 접지로 빼면 본문이 6쪽으로 줄고 제본 단가가 오른다.
펼침면 420mm로도 1km에 19.8mm가 나오니 띠는 충분히 읽힌다. 원래 폴드아웃이 하려던 일(접힘=잘린 산 / 펼침=이어진 산)은 **p2-3 펼침 그 자체**가 대신한다. 책을 펼치는 동작이 산을 잇는 동작이 된다.

## 1. 지면 배분

8쪽은 단면 2 + 펼침 3으로 떨어진다.

| 쪽 | 성격 | 내용 | 이미지 |
|---|---|---|---|
| **p1** | 단면 | 여는 면 : 제목 + 한 문장 | 능선 실루엣 1 (아주 옅게) |
| **p2-3** | 펼침 | **하나의 산** : 능선 띠 풀블리드 | 띠 1 (219점 전부) |
| **p4-5** | 펼침 | **몸의 시선** : 흔들린 사진 | 사진 10 |
| **p6-7** | 펼침 | **지도의 시선** : 트랙 전도 + 행정경계 | 지도 1 |
| **p8** | 단면 | 닫는 면 : QR + 데이터 명세 | 없음 |

구조가 그대로 주제다. **띠(데이터) → 몸 → 지도 → 돌아가는 문(QR).**
p4-5와 p6-7은 같은 하루를 두 번 보는 것이고, 둘 사이의 낙차가 이 기록집의 요지다.

## 2. 화면 구성 (쪽별)

### p1 여는 면

```
        [여백 상단 2/3]

        은평 산 아카이브
        Eunpyeong Mountain Archive

        은평의 산은 원래 하나였다.

        [하단에 능선 실루엣, 지면 폭 가득, 농도 12%]
```

- 제목은 왼쪽 정렬, 판면 왼쪽 20mm 지점에서 시작
- 능선 실루엣은 p2-3에 나올 띠와 **같은 곡선**. 미리 한 번 스치고 지나가게 한다
- 빨강 농도 12%면 종이 위에 분홍 그림자로 남는다. 읽히지 않을 정도가 맞다

### p2-3 하나의 산 (펼침)

```
┌──────────────────────── 420mm ────────────────────────┐
│ 하나의 산                                              │
│ [본문 2단, 상단 45mm]                                   │
│                                                        │
│ ░░░░░ 능선 띠 ░░░░░  (하단 풀블리드, 높이 40mm)          │
│ 0km ───────────── 10km ───────────── 21.25km          │
└────────────────────────────────────────────────────────┘
```

- 띠는 **좌우 재단선까지 빼낸다.** 여백을 남기면 산이 또 잘린다
- 219컷 전부 점으로. 사진=채운 원 / 영상=큰 원 / 7월 답사=마름모. 웹과 같은 기호를 쓴다
- 점 색은 심박 3단계. 단일톤이므로 **농도로 나눈다** : 100% / 60% / 30%
- 제본 접힘(거터)이 10.6km 지점을 지난다. 그 자리에 컷이 몰려 있으면 1km쯤 밀어 배치한다

### p4-5 몸의 시선 (펼침)

```
┌──────────────────────── 420mm ────────────────────────┐
│ ┌────┬────┬────┬────┬────┐                            │
│ │ 01 │ 02 │ 03 │ 04 │ 05 │  사진 10장                  │
│ ├────┼────┼────┼────┼────┤  5열 × 2행                  │
│ │ 06 │ 07 │ 08 │ 09 │ 10 │  장당 72 × 54mm             │
│ └────┴────┴────┴────┴────┘                            │
│ [본문, 하단 32mm, 1단 좌측]                             │
└────────────────────────────────────────────────────────┘
```

- 사진은 **원본 비율 그대로.** 크롭해서 구도를 고치면 그 순간 기록이 아니라 사진이 된다
- 캡션은 사진 아래 5pt 한 줄 : `11.23km / 177bpm / 157m / 12:09:06`
- 순서는 km 순. 왼쪽 위에서 오른쪽 아래로 읽으면 코스를 지나간다
- 단일톤 변환 : 그레이 → 레벨 18%~88% → 8×8 오더드 디더 → 빨강/종이 매핑
- **1비트 1200dpi로 넘긴다.** 그레이스케일로 넘기면 인쇄소 스크린이 한 번 더 걸려 모아레가 생긴다

### p6-7 지도의 시선 (펼침)

```
┌──────────────────────── 420mm ────────────────────────┐
│ 다섯개의 산, 하나로 이어진 은평                                  │
│ [본문 2단, 좌측 150mm]                                  │
│                        ╭─────────╮                     │
│                       ╱           ╲   트랙 전도         │
│                      │             │  높이 120mm        │
│                       ╲           ╱                     │
│                        ╰─────────╯                      │
└────────────────────────────────────────────────────────┘
```

- 트랙은 실측 GPS 14,604점. **외부 지도 타일을 깔지 않는다.** 선 하나만 남긴다
- 행정 경계 데이터 확보 완료 : `boundary.svg` (78 × 120mm, 레이어 분리됨)
- `boundary.svg` 레이어는 `#dong`(행정동 경계) / `#gu`(구 경계) / `#track` / `#cuts`(219컷) / `#crossings`(교차점 16) 다섯. 바탕 지도는 SVG 밖의 `basemap.png`가 따로 깔린다
- **교차점 16곳에 빈 원.** 선을 건너는 자리를 세어 보이게 한다. 글의 "16회"와 그림이 맞아야 한다
- **지도에 적는 건 1km 자 하나뿐이다.** 위경도 네 모서리와 1:47,500 같은 축척비는 **뺐다** : 기록집을 넘기는 사람이 읽는 숫자가 아니다
- 자 길이는 `layout.html`이 `boundary.json`을 읽어 **실제 렌더 크기에서 계산한다.** 87.1mm 폭에서 1km = 21.1mm. 지도 크기를 바꾸면 따라온다. 손으로 적지 말 것
- 참고로 현재 축척은 1:47,500(87.1 × 134mm에 지상 4,134 × 6,347m)이다. 능선 띠의 1:50,600과 **다른 값** : 띠는 21.25km를 420mm에 편 수평 축척이고 지도는 지면 실제 크기 기준이다. 한동안 지도에 1:50,600이 적혀 있었는데 띠 값을 잘못 옮긴 것이었다
- 사진은 넣지 않는다. 앞 펼침과의 대비가 이 펼침의 전부다

★**서쪽 구간은 경계선과 트랙이 거의 포개진다.** 78mm로 줄이면 두 선이 한 줄로 뭉친다.
경계선을 0.3mm쯤 바깥으로 밀거나, 경계선만 더 가늘게 빼서 두 줄로 읽히게 할 것. 이 겹침이 p6-7의 핵심이라 뭉개지면 펼침이 죽는다.

★**선만 있으면 어디가 어딘지 모른다.** 그래서 실제 지도를 바탕으로 깔았다. `print/mkbasemap.py`

```
python3 -I print/mkbasemap.py [zoom] [osm|topo] [세기]
python3 -I print/mkbasemap.py 15 topo 0.42      # 현재 값
```

- **OpenTopoMap 타일 z15, 5×7 = 35장**을 받아 붙이고 지면 bbox로 잘라 `print/basemap.png`를 만든다. 1092 × 1679px = **356dpi**
- 왜 topo인가 : OSM 기본 지도는 길이 **흰색**이라 1도로 뽑으면 선이 바탕보다 밝아 뒤집힌다. OpenTopoMap은 건물과 등고선과 길 테두리가 어두워서 그대로 선 지도가 된다. 등고선과 음영이 들어가니 **산 덩어리가 어디인지 바로 보인다** : 이 지면이 하려는 말과 맞다
- 묽게 만드는 식은 `out = 1 - (1-in) * K`, K = 0.42. ★레벨이나 대비로 깎지 말 것 : 중간톤이 뭉개져 길과 건물이 한 덩어리가 된다
- 투영은 메르카토르, 지면은 등거리원통인데 이 범위(위도 37.58–37.64)에서 **세로 오차가 0.3px**이라 그냥 늘려 맞춘다
- 타일은 `scratchpad/tiles/<소스>/`에 캐시된다. 두 번째 실행부터 네트워크를 안 탄다
- ★**출처 표기 의무.** p8에 `지도 © OpenTopoMap (CC-BY-SA) / 데이터 © OpenStreetMap contributors, SRTM`를 넣어야 한다. 빼면 라이선스 위반이다
- ★CARTO Positron은 **이제 API 키가 필요하다**(2026-11 확인). 키 없이 받으면 "API KEY REQUIRED" 워터마크 타일이 온다. Esri Light Gray는 이 지역 z16에 데이터가 없다
- 직접 그렸던 구별 면 농도 + 지명 레이어는 **걷어냈다.** 받아온 지도에 이미 지명과 길이 있다. `mkbasemap.py`가 돌 때마다 `boundary.svg`에서 `#base` / `#names` / `#paper`를 지운다
- 입고용 합성은 `basemap.png`(바탕) 위에 `boundary.svg`(트랙과 경계와 컷)를 얹는 2레이어. 같은 bbox라 겹치면 그대로 맞는다

### p3-4 : 은평둘레길

> 봉산해맞이길, 앵봉산 생태길, 백련산 불광천길, 은평 북한산 둘레길, 이말산 묘역길. 은평둘레길은 다섯 개 구간으로 이어지며, 봉산, 앵봉산, 백련산, 북한산, 이말산을 지난다. (내가 속한 러닝크루 GSRC에서는 봉산과 앵봉산을 합쳐 ‘봉앵봉’이라 부른다.)
>
> 산에는 경계가 없다. 능선은 봉산에서 북한산까지 하나로 이어진다. 경계를 그은 것은 사람이다. 산길에는 이름이 붙고, 행정구역은 구와 동으로 나뉘었다.
>
> 2026년 7월 12일과 10월 25일, 두 차례 은평둘레길을 달렸다. 두 번의 주행 경로에는 조금씩 차이가 있다. 아래는 10월 25일 달린 코스의 고도 프로파일이다. 최저 고도는 18m, 최고 고도는 233m였다.
>
> 달리며 사진과 영상을 기록한 위치에 점이 찍혀있다. 점의 농도는 촬영 당시의 심박을 나타낸다.

우측 수치 / 거리축 / 범례

```
21.25 km
누적 상승 1,171 m / 4시간 52분
평균 심박 141 bpm / 최고 심박 180 bpm
고도 18–233 m

거리축   0 / 5 / 10 / 15 / 21.25 km
범례     249 CUTS   ○ PHOTO 175 / ◎ VIDEO 74
         ◇ JULY 111 / OCTOBER 138   점의 농도 = 심박
```

★거리축에서 **20 은 뺐다** — `21.25 km` 라벨과 0.8mm 밖에 안 떨어져 한 덩어리로 읽힌다.
★범례는 **2줄이 상한이다.** 거리축 아래 빈 자리가 15.5mm 인데 4줄이면 14.9mm 라 재단선에 1mm 까지 붙는다. 위로 올리면 능선 위에 올라탄다.

### p7-8 : 다섯 개의 산

> **다섯 개의 산 / 하나로 이어진 은평**
>
> 은평둘레길을 달린 궤적을 위에서 내려다보면 하나의 선이 된다. 시작과 끝이 맞닿은 닫힌 고리다. 고리 안쪽에는 길 대신 도시가 들어서 있다.
>
> 점선은 행정구역의 경계다. 서쪽으로 갈수록 달려온 길은 행정구역의 경계와 나란히 이어진다. 산과 산을 잇는 능선이 은평과 고양을 나누는 경계가 된다. 서대문과의 경계에서도 일부 구간은 능선과 겹친다.
>
> 실제로 행정구역의 경계와 분수령이 얼마나 일치하는지 확인해봤다. 은평과 고양의 경계 7.49 km 중 70.3%가 산의 능선을 따라 이어졌다. 반면 은평과 마포의 경계에서는 분수령과 일치하는 구간이 없었다. 같은 행정구역의 경계라도 산을 지나는 곳과 도시를 지나는 곳의 모습은 달랐다.
>
> 구 경계 통과 16회 / 행정동 14개
> 은평 16.97 km / 서대문 2.27 km / 고양 2.00 km

★`서대문과의 경계에서도 일부 구간은 능선과 겹친다` 는 **아직 실측이 아니다.** 서대문 경계 전체의 분수령 비율 34.3%(§9)는 쟀지만, 그중 얼마가 백련산 구간인지는 안 재봤다. `일부` 라는 표현이라 거짓은 아니다. 다시 재려면 scratchpad 의 `dem/` 타일을 받아 `mkridgecheck.py` 를 돌려야 한다.

## 9. 검증 : 경계가 분수령을 따르는가

원고에 "경계는 능선을 따라 그어졌다"고 쓰려면 근거가 필요해서 실측했다.
결론부터 : **산 구간에서만 참이다. 전체 경계로 일반화하면 거짓이다.**

### 방법

1. 표고 데이터 : AWS Terrain Tiles(terrarium) z=14, 35타일. 이 위도에서 약 7.6m/px
2. 은평구 경계선을 **40m 간격으로 재샘플** (bbox 안 17.0km, 402점)
3. 각 점에서 **경계에 수직으로 ±150m 단면**을 15m 간격으로 뜬다
4. 중심이 양쪽 끝보다 둘 다 높으면 **분수령**(물이 양쪽으로 갈라진다), 둘 다 낮으면 골짜기
5. 임계값은 10m. 5m / 15m로도 돌려 추세를 확인했다

### 결과 (임계 10m)

| 경계 | 연장 | 분수령 | 아님 |
|---|---|---|---|
| **은평 ↔ 고양시덕양** | 7.49km | **70.3%** | 28.6% |
| 은평 ↔ 서대문 | 6.96km | 34.3% | 65.1% |
| 은평 ↔ 종로 | 1.36km | 12.5% | 87.5% |
| 은평 ↔ 마포 | 1.20km | **0%** | 100% |

임계를 5m로 낮추면 고양 78%, 15m로 올리면 65%. **고양 경계만 어느 기준에서도 견딘다.**

### 트랙 기준

| | |
|---|---|
| 경계 30m 이내를 달린 거리 | 5.18km (24.4%) |
| 경계 50m 이내 | **7.41km (34.9%)** |
| 경계 100m 이내 | 9.22km (43.4%) |

경계가 트랙 120m 안에 있는 구간은 분수령 비율 **64.8%**, 그 밖은 **22.6%**.
즉 **트랙이 지나는 쪽 경계가 곧 분수령인 쪽 경계다.** 같은 선을 두 가지로 부르고 있었던 셈이다.

### 그래서 원고를 이렇게 고쳤다

"경계는 능선을 따라 그어졌다"(전체) → **"서쪽 경계는 산에 놓여 있고, 거기서는 능선이 기준이 된다"**(한정)
그리고 대비를 추가했다 : 고양 경계는 일곱 중 다섯이 분수령, 마포 경계는 한 뼘도 아니다.
**산에서는 능선이 경계가 되고 도시에서는 길이 경계가 된다.** 틀린 문장을 고치다 더 나은 문장이 나왔다.

### 한계 (반드시 같이 읽을 것)

- 표고 원천이 **SRTM 30m급**이다. z=14로 올려 쓰지만 실제 분해능은 그만 못하다. 작은 지형은 뭉개진다
- 경계선은 통계청 2018 **일반화본**(정점 간격 약 70m). 실제 능선 마루에서 수십 미터 벗어날 수 있다 → **분수령 비율은 하한값이다.** 정밀 경계로 다시 재면 올라갈 여지가 있다
- **도시 하천은 복개되고 정비되어 이 표고 데이터에 안 보인다.** 은평/마포 경계가 불광천을 따르더라도 "골짜기"로 안 잡힌다. 수계를 따지려면 하천망 데이터가 따로 필요하다
- 따라서 "마포 경계는 수계와 무관하다"고는 **말할 수 없다.** 말할 수 있는 건 "분수령은 아니다"까지다
